## 9.2 Example trajectories

We show one harness-level and one model-level example. A third shows a failure caused by our own harness. Steps count model calls.

**Harness-level: unparsable tool calls (B0, task 040).** The task asks the agent to search delta.com for Seattle–New York flights payable with miles and to leave the results page as Chrome's active tab. On the default harness, gpt-oss-20b never issued a tool call. Its three replies were plain text:
- "I’m sorry, but I don’t have the ability to interact with a live web browser…";
- step-by-step instructions for a human;
- the same refusal again.

Stock mini-swe-agent answers each such reply with a format error and stops after three in a row. The trial ended in `RepeatedFormatError` after three calls, before any command had run. The verifier found no flight results ("Delta flight result HTML does not satisfy OSWorld check_direct_json_object"). This is the most common failure on the default harness (30 of 40 B0 trials), and it is what C0 (prompt) and C2 (tool interface) target.

The same task under V-E shows what lies underneath. With our harness, the 120b model did call tools, but it concluded that "We cannot automate a graphical browser" and submitted.

**Model-level: task beyond the model's knowledge (V-E, task 115).** The task asks the agent to remove VS Code's `ctrl+f` binding for Explorer search.
- The agent found that the settings folder was empty (steps 2–5).
- It wrote `keybindings.json` containing `[]` (step 6).
- It read the file back after C5's checklist (step 9).
- It reasoned that "The keybindings file now contains an empty array, ensuring no `ctrl+f` shortcut exists" and submitted (step 14).

The verifier expects a removal rule (`"command": "-list.find"`). An empty user file does not remove a VS Code default binding. Every harness step worked: the file was written, checked and submitted. The model lacked the domain knowledge. E and V fail the task in exactly the same way, which points to the model rather than the harness.

**Harness-induced: guardrail false positive (V, task 071).** The task asks for the image in an `.xcf` file to be pasted into `image.docx`. The agent's first command was a valid heredoc nested in `bash -lc "…"`. C2's validation rule U-FMT-03 rejected it, because the closing line read `PY"`: "heredoc 'PY' is never closed". The same rejection came five times (steps 1–4 and 6), using 5 of the trial's 17 calls. The agent then hit a missing Python package, a missing `pandoc` and a LibreOffice timeout, and ended on repeated format errors. H0, which has no such rule, solved the task.

We count this as a harness-level failure, but not as its only cause: the blocked commands also pointed at an input file that did not exist. Across all configurations, all 13 U-FMT-03 blocks were valid bash. The rule-by-rule review is in `docs/guardrail_eval_review.md`.
